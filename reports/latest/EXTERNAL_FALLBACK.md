# 外部模型回退与来源标识验证

日期：2026-11-03。当前策略在已配置服务、非原文模式且开关开启时，对知识库不足的问题直接调用该模型的通用回答。此策略取代之前“无答案只回复资料储备不够”的默认行为。

新增 7 项集成验证，全部采用临时数据库及受控 HTTP 响应：

- 未命中资料时触发外部请求，返回 external_answer，来源单独标为 external_model，检索来源为空、置信度不伪填。
- 同时保留请求模型 openrouter/free 和 API 实际响应模型，并写入 answer_provenance；知识缺口保留，不自动新增 FAQ。
- 有 FAQ 的自动回答保留知识库来源，不调用外部服务。
- 用户关闭回退、仅原文模式及离线评估开关均不发送请求。
- 429 错误脱敏显示额度问题，不把请求模型冒充已完成调用的实际模型。
- 知识库生成拒答后再走通用分支，最终来源与模型对应最终回答。
- 服务未返回 model 时明确保持实际模型未知；产品目录查询和转人工保留本地流程。

共 66 项测试通过。外部参考不计入知识库解决率；反馈可保存，但不自动训练。没有在此验证中使用真实 API Key，不能据此声称真实供应商连接或回答质量已验证。
